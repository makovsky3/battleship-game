# Repository Guide: Understanding Your Battleship Game Files

This guide explains every file in your battleship game repository, organized by importance and what you actually need to care about.

## 📖 Quick Legend

- **App files** = Your actual game code
- **src/** = Source code you might read or edit
- **configs** = Setup files for development tools
- **components/ui** = Pre-built UI widgets (mostly unused)

---

## 🎯 Tier 1: Essential Files You Will Actually Touch

These are the files you'll work with when customizing your game:

### **src/App.tsx** (708 lines)
**THE MAIN GAME FILE** - This is where everything happens!

Contains:
- All game phases (welcome screen, difficulty selection, ship placement, battle, game over)
- Board state management (tracking ships, hits, misses)
- Ship placement logic and validation
- Turn-based game flow
- All three AI difficulty levels (Easy, Medium, Hard)
- Visual rendering of both game boards
- Score tracking and win/loss detection

**When to edit:** Want to change game rules, colors, AI behavior, ship types, board size, or any gameplay feature? Start here.

### **src/App.css** (44 lines)
**Global style overrides**

Contains:
- CSS reset for the #root element (removed max-width so game can fill screen)
- A few animation keyframes (mostly unused)

**When to edit:** Rarely needed. Most styling is done with Tailwind classes directly in App.tsx.

### **README.md**
**Your project documentation**

Contains:
- How to run the game locally
- How to build for production
- Feature list and game rules
- Technology stack explanation
- Customization guide
- Link to live game

**When to edit:** Update this when you add new features or change how the game works.

## 📚 Tier 2: Supporting App Files (You May Look, Rarely Edit)

These files support the main app but you usually won't need to change them:

### **src/main.tsx** (10 lines)
**App entry point**

What it does:
- Imports React and your App component
- Mounts the App to the HTML page
- Loads global CSS

**When to edit:** Almost never. This is boilerplate that just starts your app.

### **src/index.css** (76 lines)
**Global Tailwind setup**

What it does:
- Imports Tailwind's base styles, components, and utilities
- Defines CSS variables for colors and themes
- Sets up dark mode support (not currently used)

**When to edit:** Only if you want to add custom Tailwind utilities or change the color system.

### **src/lib/utils.ts** (6 lines)
**Helper utilities**

What it does:
- Contains a `cn()` function that merges CSS class names
- Used by shadcn/ui components

**When to edit:** You don't need to. It's a utility for the pre-built components.

### **src/hooks/use-mobile.tsx** (26 lines)
**Mobile detection hook**

What it does:
- Detects if the user is on a mobile device
- Not currently used in the game

**When to edit:** You don't need to unless you want mobile-specific features.

### **src/hooks/use-toast.ts** (192 lines)
**Toast notification system**

What it does:
- Manages popup notifications
- Not currently used in the game

**When to edit:** Only if you want to add toast notifications to your game.

### **src/vite-env.d.ts** (1 line)
**TypeScript definitions for Vite**

What it does:
- Tells TypeScript how to understand Vite-specific imports
- Auto-generated

**When to edit:** Never. This is generated by Vite.

## ⚙️ Tier 4: Configuration Files (Don't Worry About These)

These files configure your development tools. They're already set up correctly and you rarely need to touch them:

### **package.json**
**Project manifest and scripts**

What it does:
- Lists all dependencies (React, TypeScript, Tailwind, etc.)
- Defines npm scripts you can run:
  - `npm run dev` - Start local development server
  - `npm run build` - Build for production
  - `npm run preview` - Preview production build
  - `npm run lint` - Check code quality

**When to edit:** Only when adding new npm packages.

### **package-lock.json**
**Exact dependency versions**

What it does:
- Auto-generated file that locks exact versions of all packages
- Ensures everyone gets the same versions

**When to edit:** Never. This is auto-generated by npm.

### **tsconfig.json** + **tsconfig.app.json** + **tsconfig.node.json**
**TypeScript compiler settings**

What they do:
- Configure how TypeScript compiles your code
- Set up the `@` alias (so `@/components/ui/button` points to `src/components/ui/button`)
- Define which files to include/exclude

**When to edit:** Almost never. These are already configured correctly.

### **vite.config.ts**
**Build tool configuration**

What it does:
- Configures Vite (the build tool and dev server)
- Sets up React plugin
- Defines path aliases

**When to edit:** Rarely. Only if you need to add plugins or change build settings.

### **tailwind.config.js**
**Tailwind CSS configuration**

What it does:
- Tells Tailwind which files to scan for CSS classes
- Defines custom colors and theme extensions
- Sets up dark mode (not currently used)

**When to edit:** Only if you want to add custom Tailwind colors or utilities.

### **postcss.config.js**
**CSS processing configuration**

What it does:
- Configures PostCSS to use Tailwind and Autoprefixer
- Ensures CSS works across browsers

**When to edit:** Never. This is standard setup.

### **eslint.config.js**
**Code quality rules**

What it does:
- Defines linting rules to catch code issues
- Helps maintain code quality

**When to edit:** Only if you want to change linting rules.

### **components.json**
**shadcn/ui configuration**

What it does:
- Stores settings for the shadcn/ui component library
- Defines component style and preset

**When to edit:** Only if you're adding more shadcn/ui components.

### **.gitignore**
**Git ignore rules**

What it does:
- Tells Git which files to ignore (node_modules, build output, etc.)
- Prevents committing unnecessary files

**When to edit:** Rarely. Only if you want to ignore additional files.

### **index.html**
**HTML shell**

What it does:
- Minimal HTML page that loads your React app
- Vite injects your app bundle here

**When to edit:** Only if you want to change the page title or add meta tags.

## 🎯 Quick Reference: Where to Change Common Things

### Change Board Size
**File:** `src/App.tsx`  
**Look for:** `const BOARD_SIZE = 10`  
**Change to:** Any number (e.g., `const BOARD_SIZE = 12`)

### Change Ships
**File:** `src/App.tsx`  
**Look for:** `const SHIPS: ShipType[] = [...]`  
**Example:** Add a new ship:
```typescript
{ name: 'Dreadnought', length: 6, placed: false }
```

### Change Colors
**File:** `src/App.tsx`  
**Look for:** Tailwind classes like:
- `bg-amber-800` (board background)
- `bg-blue-400` (water cells)
- `bg-red-600` (hit markers)
- `bg-blue-200` (miss markers)

**Change to:** Any Tailwind color (e.g., `bg-green-400`, `bg-purple-600`)

### Change AI Behavior
**File:** `src/App.tsx`  
**Look for these functions:**
- `getRandomTarget()` - Easy AI
- `getMediumAITarget()` - Medium AI
- `getHardAITarget()` - Hard AI
- `handleAITurn()` - Main AI logic

### Change Text/Labels
**File:** `src/App.tsx`  
**Look for:** Button text, messages, screen titles in the JSX (the HTML-like code)

## 💡 Pro Tips

### The `@` Alias
When you see imports like `import { Button } from '@/components/ui/button'`, the `@` is an alias for `src/`. This is configured in `tsconfig.json` and `vite.config.ts`.

So `@/components/ui/button` = `src/components/ui/button`

### Adding More shadcn/ui Components
If you want to use more pre-built components (like Dialog, Dropdown, etc.), just import them:
```typescript
import { Dialog } from '@/components/ui/dialog'
import { Select } from '@/components/ui/select'
```

They're already installed and ready to use!

### Running the Game Locally
```bash
cd /home/ubuntu/battleship-game
npm run dev
```
Then open http://localhost:5173 in your browser.

### Building for Production
```bash
npm run build
```
The built files will be in the `dist/` folder.
